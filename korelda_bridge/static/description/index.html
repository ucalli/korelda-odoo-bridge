KORELDA Bridge — Alarm to Maintenance

Turn your HVAC/BMS alarms into Odoo maintenance requests — automatically, securely, one-way.

What it does

When an alarm fires in your KORELDA installation (Modbus TCP HVAC/BMS monitoring), KORELDA sends a signed webhook and this module opens a maintenance.request in your Odoo, mapped to the right equipment.

How it works

  • One-way KORELDA → Odoo.
  • Signed webhook — HMAC-SHA256, with timestamp and seen-cache replay protection.
  • Only alarm events create requests; other events are acknowledged and ignored.
  • Deduplicated — a repeated alarm for the same rule posts a comment on the open request instead of opening a new one.
  • Cleared alarms post a comment — the request is never auto-closed. A person decides when the work is done.

Setup

  1. Install the module.
  2. Set the shared secret in Settings → Maintenance.
  3. Map KORELDA rule ids to equipment. An optional default equipment covers single-site setups.

Unmapped alarms still open a request, clearly flagged — nothing is lost.

What it does NOT do

  • No write-back to KORELDA, no remote control, no polling.
  • Rule, threshold and device configuration stay in KORELDA.
  • Self-hosted Odoo only (Odoo.sh / on-premise) — not Odoo Online/SaaS.

Data handling

The module receives alarm metadata (rule id and name, severity, timestamp and, when the sender includes them, the alarm subject and message) via the signed webhook and stores it in your Odoo database. Nothing is sent to third parties. See https://www.korelda.ai for details.

Scope

Modbus TCP HVAC/BMS monitoring.
